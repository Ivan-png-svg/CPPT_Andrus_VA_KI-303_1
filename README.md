## 1. Опис проєкту

Консольна Java-програма читає каталог книжок із CSV-файлу, перевіряє коректність записів, обчислює статистичні показники
та формує текстовий звіт.

У лабораторній роботі №1 реалізовано базову обробку каталогу, аргументи командного рядка та автоматизовані тести.

У лабораторній роботі №2 виконано рефакторинг із використанням окремих класів, Java `record`, шаблону Builder, розширено
тестування та виправлено зауваження до лабораторної №1.

У лабораторній роботі №3 додано ієрархію `Book` → `PrintedBook` / `ElectronicBook`, enum `BookFormat`, поліморфний розрахунок часу читання, рівність об’єктів та демонстрацію `sealed` і pattern matching `switch` у Java 21. Історичний звіт ЛР №3 доступний у гілці `Lab_3`; поточний `REPORT.md` присвячений ЛР №4.

Розробку лабораторної №2 виконано в гілці `Lab_2`, після чого зміни об’єднано з `main`. Початковий стан лабораторної №1 з
бережено в гілці `Lab_1`. Додаткові виправлення після перевірки коду виконано в гілці `fix/lab2-review` (коміт `656e8b7`)
 та об’єднано через Pull Request #11. Завдання GitHub Issues #4–#7 закриті.

## 2. Формат вхідних даних

Кожен CSV-рядок має формат:

```text
title;author;pages;price
```

Поля:

- `title` — назва книжки (`String`);
- `author` — автор (`String`);
- `pages` — кількість сторінок (`int`);
- `price` — ціна (`double`).

Роздільник полів — крапка з комою (`;`).

Приклад:

```csv
Кобзар;Тарас Шевченко;720;450.00
Лісова пісня;Леся Українка;180;320.00
Місто;Валер'ян Підмогильний;304;280.00
```

За замовчуванням програма читає файл:

```text
data/input.csv
```

## 3. Валідація записів

Запис вважається коректним, якщо:

1. Рядок не порожній.
2. Містить рівно чотири поля.
3. Назва книжки та автор не порожні.
4. Кількість сторінок є цілим числом, більшим за нуль.
5. Ціна є числом, не меншим за нуль.
6. Ціна є скінченним числом: `NaN`, `Infinity` та `-Infinity` заборонені.

Некоректні записи не враховуються в статистиці. Для кожного такого запису у звіті зазначаються номер рядка та причина пом
илки.

## 4. Обчислювані показники

Програма визначає:

- кількість коректних записів;
- кількість некоректних записів;
- середню кількість сторінок;
- найдорожчу книжку;
- сумарну вартість каталогу;
- перелік помилок вхідних даних.

Для підсумовування кількості сторінок використовується тип `long`, що запобігає переповненню, характерному для попередньо
ї реалізації з `int`, у перевіреному сценарії.

## 5. Реалізація лабораторної №2

### 5.1. Клас Book

`Book` — незмінний (`immutable`) клас, який представляє книжку.

Містить поля:

```java
private final String title;
private final String author;
private final int pages;
private final double price;
```

Основні можливості:

- конструктор із перевіркою даних;
- геттери без сеттерів;
- статичний метод `Book.fromCsv(String)`;
- метод `toString()`;
- Javadoc для публічних методів.

Метод `fromCsv()` відповідає за розбір CSV-рядка. Це дозволило прибрати дублювання логіки перевірки з `Main.java`.

### 5.2. Record PagePrice

`PagePrice` — Java `record` для зберігання кількості сторінок та ціни:

```java
public record PagePrice(int pages, double price)
```

Компактний конструктор перевіряє коректність обох значень.

Java автоматично забезпечує методи доступу `pages()` і `price()`, а також `equals()`, `hashCode()` і `toString()`.

### 5.3. Book.Builder

Реалізовано вкладений клас `Book.Builder` для покрокового створення незмінних об'єктів.

Приклад:

```java
Book book = Book.builder()
        .title("Кобзар")
        .author("Тарас Шевченко")
        .pages(720)
        .price(450.00)
        .build();
```

Перевірка даних виконується конструктором `Book` під час виклику `build()`. Ціну необхідно явно задати методом `.price(..
.)`: якщо її не вказано, `build()` генерує `IllegalArgumentException`. При цьому явно задана ціна `0.0` дозволена. Поведі
нку перевіряє тест `testBuilderRejectsMissingPrice()`.

Повторне використання Builder не змінює раніше створених об'єктів.

### 5.4. Рефакторинг Main

Після рефакторингу:

- CSV-записи перетворюються на об'єкти через `Book.fromCsv()`;
- коректні книжки зберігаються в `List<Book>`;
- для статистики використовується `PagePrice`;
- загальна кількість сторінок підсумовується в `long`;
- формат текстового звіту з лабораторної №1 збережено.

## 6. Виправлення зауважень до лабораторної №1

### Зауваження 1 — NaN та Infinity

**Проблема:** попередня перевірка `price < 0` не відхиляла всі нескінченні та невизначені числові значення.

**Виправлення:** додано `Double.isFinite(price)` у `Book` і `PagePrice`.

**Перевірка:** тестовий CSV із `NaN`, `Infinity`, `-Infinity` та однією коректною ціною.

Результат: 1 коректний і 3 некоректні записи.

### Зауваження 2 — переповнення int

**Проблема:** сума сторінок зберігалася у змінній типу `int`.

**Виправлення:** у `Main.processCatalog()` використано `long totalPages`.

**Перевірка:** два записи по 2 000 000 000 сторінок.

Результат: середня кількість сторінок — `2000000000.00`, без переповнення.

### Зауваження 3 — apache.snapshots та ow2-snapshot

Проведено дослідження конфігурації Maven.

Виконані перевірки:

- `help:effective-pom`;
- `help:effective-settings`;
- `help:active-profiles`;
- детальний журнал Maven із параметром `-X`;
- аналіз локальних POM-файлів Maven;
- перевірка локальних метаданих Maven.

Результати:

- У перевірених Effective POM та Effective Settings назви `apache.snapshots` і `ow2-snapshot` не знайдено.
- Для основного проєкту команда `help:active-profiles` не показала активних профілів.
- У локальних батьківських POM-файлах Apache Maven виявлено оголошення snapshot-репозиторіїв.
- У `maven-parent-45.pom` знайдено профіль, який містить репозиторій `https://repository.apache.org/snapshots` та активує
ться за властивістю `apache.snapshots`.
- У журналі Maven виявлено використання локальних метаданих `prefixes-apache.snapshots.txt`.
- Під час виконання Maven Shade Plugin також спостерігалося повідомлення про `ow2-snapshot`.

Таким чином, назви snapshot-репозиторіїв зустрічаються в конфігурації та роботі Maven-плагінів, хоча не оголошені безпосе
редньо в `pom.xml` цього проєкту. Точний ланцюжок успадкування конфігурації для конкретного запуску не встановлено остато
чно.

## 14. Лабораторна робота №3 — спадкування та поліморфізм

**Варіант 1: каталог книжок.** Лабораторна №3 розширює попередню модель, не змінюючи формат CSV та основний сценарій формування звіту.

### 14.1. Ієрархія класів

- `Book` — спільний `sealed` клас із назвою, автором, кількістю сторінок і ціною; збережено створення звичайного `Book` для сумісності з ЛР №2.
- `PrintedBook` — `final` підтип із властивістю `hardcover`.
- `ElectronicBook` — `final` підтип із властивістю `fileSizeMb`.
- `BookFormat` — enum із форматами `PRINTED` та `ELECTRONIC` і методом `label()`.
- `BookCatalogDemo` — окрема демонстрація поліморфізму й pattern matching; не підміняє `Main`.

### 14.2. Поліморфна поведінка

Спільний метод `calculateReadingHours()` викликається через змінну типу `Book`. Для друкованої книжки розрахунок — `pages / 30.0`, для електронної — `pages / 40.0`. Наприклад, для 300 сторінок результати становлять 10.00 та 7.50 год відповідно.

`equals()` і `hashCode()` враховують конкретний клас та властивості книжки; у підтипах враховуються також їхні власні поля.

### 14.3. Завдання із зірочкою

`Book` оголошено як `sealed` з дозволеними підтипами `PrintedBook` і `ElectronicBook`. У `BookCatalogDemo.describeBook()` використано Java 21 pattern matching `switch` без `default`:

- `case PrintedBook` — опис типу палітурки;
- `case ElectronicBook` — опис розміру файлу;
- `case Book` — обробка об'єктів безпосередньо базового конкретного класу.

Остання гілка потрібна, тому що `Book` не є абстрактним і може створюватися безпосередньо. Поліморфний розрахунок часу читання **не дублюється** у `switch`.

### 14.4. Запуск демонстрації

```powershell
mvn clean verify
java -cp target\classes ua.lpnu.kzp.BookCatalogDemo
```

У Windows PowerShell 4.0 старі налаштування консолі можуть некоректно показувати українські символи; це окреме питання кодування виводу, а не логіки розрахунків.

### 14.5. Тести ЛР №3

Додано `BookInheritanceTest` для ієрархії та `BookCatalogDemoTest` для перевірки гілок `switch` і поліморфної поведінки. Разом із тестами попередніх лабораторних очікується 47 тестів, **але остаточну кількість та успішність необхідно підтвердити командою `mvn clean verify`**.

Розробка ЛР №3 ведеться в гілці `Lab_3`; відповідні GitHub Issues і Pull Request оформлюються перед завершенням роботи.

## 15. Лабораторна робота №4 — Stream API (варіант 1 «Бібліотека»)

### 15.1. Мета та сумісність

Реалізувати обробку каталогу книжок засобами Java Stream API, не порушуючи роботу лабораторних №1–3. Основна програма `Main` і далі читає CSV `title;author;pages;price`, перевіряє записи та створює попередній звіт. Для Stream-запитів у `Book` передбачено додаткові метадані року публікації (`publicationYear`) та жанру (`BookGenre`). Для старих CSV-записів використовуються значення за замовчуванням `0` та `UNSPECIFIED`.

### 15.2. Реалізовані запити

| Операція | Stream API | Результат демонстрації |
|---|---|---|
| Книги від 2020 року включно | `filter` | `Alpha, Beta, Delta, Alpha` |
| Назви книжок | `map` | `Alpha, Beta, Gamma, Delta, Alpha, Epsilon` |
| Кількість за жанрами | `groupingBy` + `counting` | `HISTORY=1, FANTASY=1, FICTION=2, SCIENCE=2` |
| Статистика сторінок | `summarizingInt` | `count=6, sum=1800, min=100, max=550, avg=300.00` |
| Топ-5 за сторінками | `sorted` + `limit` | `Gamma, Alpha, Beta, Delta, Alpha` |
| Пошук за назвою | `findFirst` + `Optional` | `Alpha → Author A`; відсутня назва → `Optional.empty` |
| Завдання із зірочкою | Вкладений `groupingBy` | Кількість книжок за жанром і роком |

Сортування топу: кількість сторінок за спаданням, за однакової кількості — назва за зростанням. Запити винесені до `BookQueries`, демонстрація — до `Lab4Demo`, тести — до `BookQueriesTest`.
