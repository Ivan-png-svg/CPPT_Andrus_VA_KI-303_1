## 1. Мета роботи

Опанувати конвеєри Stream API у Java 21 для фільтрації, перетворення, групування, статистики, сортування й пошуку даних; використати `Optional`, перевірити крайові випадки та зберегти сумісність із попередніми лабораторними роботами.

## 2. Середовище та вихідний проєкт

- Java 21, Maven і Maven Wrapper, JUnit 5, SpotBugs.
- Пакет: `ua.lpnu.kzp`.
- Гілка розробки: `Lab_4`; ціль Pull Request: `main`.

- Основа — каталог книжок із лабораторних №1–3: `Book`, `PrintedBook`, `ElectronicBook`, `Main`, обробка CSV та текстовий звіт.

## 3. Постановка задачі

Для набору книжок реалізувати методи Stream API: відбір за роком публікації (від 2020 включно), отримання назв, підрахунок книжок за жанрами, статистику сторінок, топ-5 за сторінками зі вторинним сортуванням за назвою, пошук за назвою з `Optional`. Додаткове завдання — вкладене групування за жанром і роком.

## 4. Реалізація

Додано `BookGenre` та необов'язкові для попереднього CSV метадані `publicationYear` і жанр у `Book`. Старий формат `title;author;pages;price` не змінено; для старих записів передбачені значення року `0` та жанру `UNSPECIFIED`.

Запити зосереджено в `BookQueries`, демонстраційний набір — у `Lab4Demo`. Використано `filter`, `map`, `Collectors.groupingBy`, `Collectors.counting`, `Collectors.summarizingInt`, `sorted`, `limit` і `findFirst`. Для топу порівняння сторінок розгортається за спаданням **до** додавання `thenComparing` за назвою, тому назви з однаковою кількістю сторінок сортуються за зростанням.

`Optional` дозволяє безпечно представити відсутність результату. Запити не повинні змінювати вхідну колекцію.

## 7. Порівняння циклової обробки та Stream API

| Операція | Цикловий підхід | Реалізація Stream API |
|---|---|---|
| Відбір книжок від 2020 року | Перебір записів і перевірка року через `if` | `filter(book -> book.getPublicationYear() >= 2020)` |
| Отримання назв | Перебір і додавання назви до списку | `map` і `toList` |
| Кількість книжок за жанрами | Накопичення лічильників у `Map` | `groupingBy` разом із `counting` |
| Статистика сторінок | Окреме обчислення кількості, суми, мінімуму, максимуму та середнього | `summarizingInt` |
| Топ-5 за сторінками та назвою | Сортування за двома критеріями й вибір перших п'яти | `sorted` з `reversed` і `thenComparing`, далі `limit(5)` |
| Пошук за назвою | Перебір до першого збігу | `filter` і `findFirst`, результат `Optional` |

**Порівняння результатів.** На контрольному наборі з шести книжок потоки повертають чотири книжки від 2020 року, шість назв, розподіл за жанрами `HISTORY=1`, `FANTASY=1`, `FICTION=2`, `SCIENCE=2` та статистику сторінок: кількість `6`, сума `1800`, мінімум `100`, максимум `550`, середнє `300.00`. Топ-5: `Gamma`, `Alpha`, `Beta`, `Delta`, `Alpha`. Для назви `Alpha` повертається перший запис, для відсутньої назви — `Optional.empty`. Ці результати узгоджуються з відповідними цикловими правилами відбору, підрахунку та впорядкування; окремого автоматизованого тесту, що порівнює дві реалізації на одному наборі, у наданих доказах немає.

**Збереження попередньої поведінки.** Запуск старого CSV-звіту після змін показав попередні контрольні показники: п'ять коректних і п'ять некоректних записів, середнє `344.80`, найдорожча книжка «Кобзар» (`450.00 грн`), загальна вартість `1540.00 грн`. Побайтове порівняння з файлом попереднього звіту не виконувалося.

## 12. Контрольні питання (усі 20 з методички ЛР4)

**1. Чим потік відрізняється від колекції?** Колекція зберігає дані, Stream описує одноразове обчислення над джерелом і не зберігає елементи.

**2. Які частини має типовий конвеєр Stream API?** Джерело, нуль або більше проміжних операцій та кінцева операція.

**3. Чому проміжні операції називають лінивими?** Вони не виконують обхід джерела до запуску кінцевої операції.

**4. Що робить filter і який тип має його предикат?** filter залишає елементи, для яких Predicate<T> повертає boolean true.

**5. Чим map відрізняється від mapToDouble?** map повертає Stream<R>, а mapToDouble створює примітивний DoubleStream без пакування double.

**6. Для чого застосовується distinct і від чого залежить його результат?** Видаляє повтори; для об’єктів використовує equals і hashCode.

**7. Чому порядок sorted().limit(N) відрізняється від limit(N).sorted()?** У першому випадку сортується вся вибірка перед відсіканням, у другому — лише перші N вхідних елементів.

**8. Яку роль виконує кінцева операція?** Запускає конвеєр і створює результат або побічний ефект; після неї потік повторно не використовують.

**9. Коли застосовується Collectors.joining?** Коли рядкові елементи потрібно об’єднати в один рядок з роздільником, префіксом або суфіксом.

**10. Як groupingBy будує карту груп?** Застосовує функцію класифікації до кожного елемента і збирає значення за ключами.

**11. Як отримати суму в кожній групі через downstream collector?** Передати groupingBy(ключ, Collectors.summingInt(...)) або summingDouble(...).

**12. Які показники містить DoubleSummaryStatistics?** Кількість, суму, мінімум, максимум і середнє.

**13. Які значення має статистика для порожнього потоку?** count=0, sum=0, average=0, min=+Infinity, max=-Infinity; у звіті це треба пояснити.

**14. Як утворюється складений компаратор?** Comparator.comparing(...) або comparingInt(...), після чого thenComparing(...) для другого ключа.

**15. Чому reversed() потрібно застосовувати до окремого ключа до thenComparing?** Інакше reversed() змінить напрямок порівняння всього складеного компаратора, включно з другим ключем.

**16. Яку проблему розв’язує Optional у методі пошуку?** Явно представляє наявний або відсутній результат замість повернення null.

**17. Чим відрізняються orElse, orElseThrow і ifPresent?** orElse повертає значення або запасне; orElseThrow кидає виняток за відсутності; ifPresent виконує дію лише за наявності.

**18. Чому накопичення результату через зовнішній змінний список у forEach небажане?** Це побічний ефект, що ускладнює читання і створює ризик гонок у паралельних потоках; краще collect або toList.

**19. Які властивості мають бути перевірені під час рефакторингу циклу на потік?** Порядок, значення і статистику, дублікати, порожній вхід, межі N, відсутній пошук, незмінність джерела та попередні тести.

**20. За яких умов паралельний потік може бути виправданим?** На достатньо великому наборі, для незалежних операцій без спільного змінного стану, коли вимірювання показує перевагу.
