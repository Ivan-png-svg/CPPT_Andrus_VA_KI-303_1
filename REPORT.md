## 4. Базовий тип `Book`

`Book` містить спільні властивості книжки: `title`, `author`, `pages`, `price`. Збережено валідацію даних, геттери, `fromCsv()` та Builder для сумісності з попередніми роботами.

У ЛР №3 клас оголошено як `sealed` із дозволеними прямими підкласами `PrintedBook` та `ElectronicBook`. `Book` залишається **конкретним**, а не абстрактним класом: попередній код може створювати `new Book(...)` і використовувати Builder без змін.

Метод `calculateReadingHours()` у базовому класі розраховує час із припущенням **30 сторінок за годину**. Метод `getFormat()` повертає `BookFormat.PRINTED`.

## 5. Підкласи `PrintedBook` та `ElectronicBook`

### 5.1. `PrintedBook`

`PrintedBook` — `final`-нащадок `Book` із додатковим полем `hardcover` (тверда чи м’яка палітурка). Метод `calculateReadingHours()` перевизначено: кількість сторінок ділиться на **30 сторінок/год**. Формат — `PRINTED`.

### 5.2. `ElectronicBook`

`ElectronicBook` — `final`-нащадок `Book` із полем `fileSizeMb`. Значення розміру файлу має бути додатним і скінченним. Метод `calculateReadingHours()` використовує **40 сторінок/год**. Формат — `ELECTRONIC`.

### 5.3. Приклад поліморфізму

```java
List<Book> books = List.of(
    new PrintedBook("Кобзар", "Тарас Шевченко", 300, 450.0, true),
    new ElectronicBook("Основи Java", "Іван Петренко", 300, 200.0, 5.5)
);

for (Book book : books) {
    System.out.println(book.calculateReadingHours());
}
```

Для друкованої книжки результат становить **10,00 год**, для електронної — **7,50 год**. Виклик здійснюється через посилання типу `Book`, а реалізація методу визначається фактичним класом об’єкта.

## 6. Перелік `BookFormat`

Перелік `BookFormat` містить константи `PRINTED` та `ELECTRONIC`. Метод `label()` повертає їхні україномовні назви. `enum` обмежує допустимі значення формату й забезпечує перевірку типів під час компіляції.

## 7. Рівність об’єктів і хешування

Для `Book`, `PrintedBook` та `ElectronicBook` реалізовано `equals()` і `hashCode()`.

- У `Book` враховуються назва, автор, кількість сторінок і ціна.
- У `PrintedBook` додатково враховується `hardcover`.
- У `ElectronicBook` додатково враховується `fileSizeMb`.
- Об’єкти різних фактичних класів не вважаються рівними.

Контракт вимагає, щоб рівні за `equals()` об’єкти мали однаковий `hashCode()`. Це важливо для `HashSet` і `HashMap`: наприклад, повторне додавання рівної книжки до множини не має збільшувати кількість елементів. Тести перевіряють рівність, хешування та поведінку множини.

## 9. Додаткове завдання: `sealed` та вичерпний `switch`

Ієрархію обмежено засобами Java 21:

```java
public sealed class Book permits PrintedBook, ElectronicBook {
    // Спільні поля та методи книжки.
}
```

Обидва дозволені підкласи оголошено як `final`. У демонстрації використано:

```java
return switch (book) {
    case PrintedBook printed -> printed.isHardcover()
            ? "Друкована книжка у твердій палітурці"
            : "Друкована книжка у м'якій палітурці";
    case ElectronicBook electronic -> String.format(
            Locale.ROOT,
            "Електронна книжка, розмір файлу: %.2f МБ",
            electronic.getFileSizeMb());
    case Book base -> "Звичайна книжка каталогу: " + base.getTitle();
};
```

**Чому немає `default`:** базовий `Book` — конкретний клас, тому можливі його безпосередні екземпляри. Гілка `case Book base` охоплює їх і будь-які інші значення типу `Book`, які не були оброблені попередніми гілками. Завдяки цьому `switch` є вичерпним.

**Обмеження демонстрації:** оскільки `case Book` охоплює всі підтипи, додавання нового дозволеного підкласу не обов’язково викличе помилку компіляції. Отже, реалізація демонструє `sealed` і вичерпний pattern matching `switch`, але не гарантує повідомлення компілятора про кожен новий підтип. Збереження конкретного `Book` обране заради сумісності з попередніми лабораторними.

**Фактичні результати перевірок:**

| Перевірка | Результат |
|---|---|
| Побайтове порівняння `SequenceEqual` | `False` |
| Порівняння рядків `Compare-Object` | Відмінностей немає |
| Розмір контрольного звіту | 745 байтів |

### 14.2. Контрольні питання

**Що таке спадкування?** Механізм створення спеціалізованого класу на основі базового. У проєкті `PrintedBook` і `ElectronicBook` успадковують властивості `Book`.

**Що таке поліморфізм?** Можливість викликати спільний метод через посилання базового типу, отримуючи реалізацію відповідно до фактичного класу об’єкта. Приклад — `calculateReadingHours()`.

**Навіщо потрібен `@Override`?** Анотація позначає перевизначення успадкованого методу та допомагає компілятору виявляти помилки сигнатури.

**Навіщо узгоджувати `equals()` і `hashCode()`?** Хеш-колекції використовують обидва методи. Якщо об’єкти рівні за `equals()`, їхні хеш-коди повинні збігатися.

**Чим `enum` кращий за рядкові константи?** `enum` задає обмежений набір значень із перевіркою типів під час компіляції.

**Що дає `sealed`?** Дозволяє явно визначити допустимі прямі підкласи та полегшує аналіз ієрархії.

**Чим pattern matching `switch` відрізняється від поліморфізму?** `switch` явно вибирає гілку за типом, тоді як поліморфізм передає вибір реалізації механізму віртуальних методів. У проєкті час читання обчислюється поліморфно, а `switch` формує опис типу.

**Для чого потрібні CI і SpotBugs?** CI автоматизує збирання й перевірки на різних платформах; SpotBugs аналізує байткод для виявлення потенційних дефектів.
