## 2. Мета роботи

Метою роботи є створення та перевірка кросплатформного Java-проєкту з використанням Maven, реалізація читання та валідації даних із CSV-файлу, обчислення показників відповідно до варіанта, автоматизоване тестування та формування звіту.

У межах предметної частини реалізовано програму для обробки каталогу книжок.

У результаті:
- створено Maven-проєкт на Java 21;
- налаштовано UTF-8;
- підключено JUnit 5;
- реалізовано читання та валідацію CSV;
- реалізовано показники варіанта №1;
- реалізовано виведення звіту в консоль та `out/report.txt`;
- реалізовано параметри `--help`, `--version`, `--input`, `--output`;
- підготовлено Maven Wrapper;
- у проєкті передбачено статичний аналіз і CI.

## 3. Постановка задачі

### Формат запису

Для варіанта №1 «Каталог книжок» використовується формат:

```text
title;author;pages;price
```

Поля:
- `title` — назва книжки (`String`);
- `author` — автор (`String`);
- `pages` — кількість сторінок (`int`);
- `price` — ціна (`double`).

Дані зберігаються у CSV-файлі в кодуванні UTF-8. Роздільник — `;`.

### Валідація

Програма перевіряє:
- порожній рядок;
- кількість полів — рівно 4;
- непорожні `title` та `author`;
- правильність числового формату `pages` і `price`;
- `pages > 0`;
- `price >= 0`.

Некоректні записи не беруть участі в обчисленнях. Для кожного помилкового запису виводяться номер рядка та причина.

### Показники варіанта №1

Програма визначає:
1. кількість коректних записів;
2. середню кількість сторінок;
3. найдорожчу книгу;
4. сумарну вартість каталогу.

## 4. Структура програми

Основний клас:

```text
ua.lpnu.kzp.Main
```

Він відповідає за:
- обробку аргументів командного рядка;
- читання `data/input.csv`;
- перевірку записів;
- перетворення числових значень;
- обчислення показників;
- формування текстового звіту;
- виведення звіту в консоль;
- запис звіту в UTF-8.

Основний потік даних:

```text
data/input.csv
      ↓
читання UTF-8
      ↓
розбиття рядка на 4 поля
      ↓
валідація
      ↓
обчислення показників
      ↓
консоль + out/report.txt
```

Основна структура:

```text
.
├── .github/
│   └── workflows/
│       └── ci.yml
├── .mvn/
│   └── wrapper/
├── data/
│   └── input.csv
├── out/
│   └── report.txt
├── src/
│   ├── main/
│   │   └── java/
│   │       └── ua/lpnu/kzp/Main.java
│   └── test/
│       └── java/
│           └── ua/lpnu/kzp/MainTest.java

```

## 5. Інфраструктура

### Maven та Maven Wrapper

Для керування проєктом використовується Maven. Maven Wrapper дає змогу запускати збірку через:

```powershell
.\mvnw.cmd
```

На локальній машині також перевірено запуск через встановлений Maven:

```powershell
mvn -B clean test
```

### Java та кодування

Використовується Java 21.

Читання та запис текстових файлів виконуються явно в UTF-8:

```java
StandardCharsets.UTF_8
```

Для шляхів використовується `Path`, що не прив'язує програму до Windows-роздільників.

Для числового форматування використовується `Locale.ROOT`, а для переносів рядків — платформонезалежний механізм Java.

### Тестування

Для автоматизованого тестування використовується JUnit 5.

```powershell
.\mvnw.cmd -B clean test
```

```powershell
java -cp target/classes ua.lpnu.kzp.Main --input data/input.csv --output out/report.txt
```

```text

Середня кількість сторінок: 344.80
```

## 11. Відповіді на контрольні питання

1. **Яке призначення файла `pom.xml`?**  
   `pom.xml` описує Maven-проєкт: його координати, версію Java, залежності, плагіни та параметри збірки.

2. **Чим відрізняються фази `test`, `verify` і `package`?**  
   `test` запускає тести, `package` створює пакет проєкту, наприклад JAR, а `verify` виконує додаткові перевірки після пакування.

3. **Навіщо потрібен Maven Wrapper?**  
   Він дозволяє запускати Maven-проєкт із визначеною для проєкту версією Maven без необхідності окремо налаштовувати однакову версію на кожному комп'ютері.

4. **Яку роль відіграє метод `main`?**  
   Це точка входу в Java-застосунок.

5. **Чим примітивний тип відрізняється від `String`?**  
   `int` і `double` є примітивними типами, а `String` — класом, об'єкти якого представляють текст.

6. **Чому середнє потрібно обчислювати в `double`?**  
   Тому що результат ділення може мати дробову частину.

7. **Що станеться, якщо `Integer.parseInt` отримає `"abc"`?**  
   Буде згенеровано `NumberFormatException`, який програма повинна коректно обробити.

8. **Чому не можна мовчки пропускати помилковий рядок?**  
   Користувачеві потрібно повідомити, який рядок відхилено і з якої причини.

9. **Як `String.split(";", -1)` обробляє порожні поля?**  
   Другий аргумент `-1` зберігає також порожні елементи наприкінці рядка, тому можна правильно перевірити кількість полів.

10. **Чому для шляхів використовується `Path`?**  
    `Path` надає стандартний кросплатформний спосіб роботи зі шляхами без ручного використання Windows- або Unix-роздільників.

11. **Навіщо явно задавати `StandardCharsets.UTF_8`?**  
    Щоб результат не залежав від системного кодування і українські символи читалися та записувалися однаково.

12. **Навіщо використовувати платформонезалежні переноси рядків?**  
    Windows, Linux і macOS можуть використовувати різні представлення нового рядка, тому платформонезалежний підхід робить програму переносимою.

13. **Які дані перевіряються у варіанті №1?**  
    Рядок повинен містити 4 поля: `title`, `author`, `pages`, `price`. Назва й автор мають бути непорожніми, `pages` — цілим числом більшим за 0, а `price` — числом, що не є від'ємним.

14. **Які тести можуть виявити помилку в обчисленні середнього?**  
    Тест із кількома коректними книжками, для яких наперед відома сума сторінок та очікуване середнє значення.

15. **Яке призначення статичного аналізатора?**  
    Він шукає потенційні дефекти та небезпечні шаблони у програмі без необхідності проходження конкретного сценарію виконання.

16. **Яку роль виконує GitHub Actions?**  
    GitHub Actions автоматизує збірку, тестування та інші CI-перевірки після змін у репозиторії.

17. **Що має містити GitHub Issue на дефект?**  
    Назву, опис проблеми, кроки відтворення, очікуваний і фактичний результат та, за потреби, додаткові матеріали.

18. **Що потрібно вказати в розділі про академічну доброчесність?**  
    Потрібно вказати використані ШІ-інструменти, для чого вони застосовувалися, які рекомендації були прийняті та як результати перевірялися.

19. **Яку роботу виконують ролі DevOps і Валідатор?**  
    DevOps працює з інфраструктурою збірки, Maven і CI, а Валідатор перевіряє коректність даних, крайові випадки та тести.

20. **Чому `String.split(";", -1)` важливий для цієї програми?**  
    Він дозволяє не втрачати порожні поля CSV-рядка, що важливо для правильної валідації структури запису.
